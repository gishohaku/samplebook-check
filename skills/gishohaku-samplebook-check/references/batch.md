# 複数の本を一括でチェックする場合

運営スタッフが提出物をまとめて確認する使い方（zip に多数のPDFが入っているなど）。本ごとに前提を尋ねたり内容チェックを確認したりするのは現実的でないので、次のように進める。

- **前提**: 種別は「書籍」、印刷形態は不明として扱う。印刷所名は、記載があれば ✅、なければ「印刷版なら❌、コピー本・電子版のみなら不要」と条件付きで示す。ファイル名や奥付から電子版・コピー本とわかるものはそれに従う。
- **ファイル名**: `#Uxxxx` 形式でエンコードされていることがあるので、デコードしてから一覧にする。
- **画像ファイル**: 見本誌の対象か（本の一部か、提出不要のグッズか）だけを判断する。表紙だけで本文がなければ「本文の提出が必要」と指摘する。
- **奥付**: 全冊チェックする。同じ著者の複数の本で連絡先の表記が違う（アカウント名の綴り違いなど）場合は、誤記の可能性として指摘する。
- **一次レビュー**: 全冊に `triage.py` をかけ、リスクが高・中の本を挙げる。
- **内容チェック**: 奥付のレポートを出したあと、内容チェックをするか、するならどの本かを一度だけ尋ねる。リスクが高の本は「強く推奨」として先頭に挙げる。
- **レポートの順序**: 総括 → 要対応の一覧（❌・⚠️ があるものだけ）→ 全冊の一覧表。全冊の詳細を並べると読み切れないため。
- **データの扱い**: 他の著者の出版前の原稿を扱う。SKILL.md の「入力データの扱い」を同じように守り、レポートは依頼者以外に共有しない前提で書く。

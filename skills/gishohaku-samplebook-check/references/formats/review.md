# Re:VIEW の奥付

## 仕組み

Re:VIEW は設定値から奥付を自動生成する。有効・無効は出力形式ごとに決まり、PDFでは `pdfmaker:` の下の `colophon`（公式のサンプル設定では `true`）が、最上位の `colophon` より優先される。
奥付に関わる主なキーと、技書博の項目の対応は次のとおり。

| 技書博の項目 | config.yml のキー | 備考 |
|---|---|---|
| 書名 | `booktitle` | |
| 発行サークル名 | `pbl`（発行所） | サークル名を発行所として入れるのが一般的 |
| 発行責任者名 | `aut`（著者） | 文字列・配列・`{name: ...}` の配列のいずれか |
| 連絡先 | `contact` | |
| 初回発行日 | `history` の最初の要素、なければ `date` | `history` は版ごとの配列で、`history[0][0]` が初版第1刷 |
| 印刷所名 | `prt` | |

`inherit` で別の設定ファイルを継承している場合があるので、`check_review_config.py` は継承を解決してから検査する。
`colophon_order` を指定していると、そこに含まれないキーは奥付に出力されない。

## 検証の状況

このスクリプトは、Re:VIEW 公式のサンプル設定のキーに合わせて作ってあるが、実際の出版プロジェクトでの検証は十分でない。Re:VIEW Starter など派生テンプレートは、設定ファイルの構成や奥付の作り方が異なることがある。結果は「直す場所の手がかり」として使い、判定はビルド後のPDFで行う。

## よくある落とし穴

- **テンプレートの初期値が残っている**: 書名や著者、日付がサンプルの値のまま。日付が数年前になっていたら疑う。
- **独自の奥付**: TechBooster のテンプレートなど、サークル独自のテンプレートでは奥付を `.re` ファイル、スタイルファイル（`sty/` 配下）、レイアウトに直接書いていることがある。この場合 `colophon: false` でも奥付は存在しうる。`check_review_config.py` の `custom_colophon_files` を開いて中身を確認する。
- **設定と出力のずれ**: スタイルの上書きで一部のキーが表示されないことがある。ビルド済みPDFがあれば必ずそちらで最終確認する。

## 手順

1. `python scripts/check_review_config.py <プロジェクト>` を実行する
2. `findings` を `colophon-rules.md` の判定に当てはめる
3. `colophon` が無効なら `custom_colophon_files` を開いて、独自奥付の記述から6項目を探す
4. 内容チェックを行う場合は、可能ならビルド済みPDFを使う。PDFがなければ `.re` ファイルを `catalog.yml` の順に読む

# 技書博 見本誌セルフチェック（Claude 用スキル）

[技術書同人誌博覧会（技書博）](https://gishohaku.dev/)に出展するサークルが、見本誌を提出する前に、自分の本を確認するための Claude 用スキルです。技書博のスタッフが作成し、公開しています。運営事務局の見本誌確認と同じ観点でチェックし、提出後の差し戻しや当日の頒布中止を防ぐことを目的にしています。

> **このスキルの結果は、運営事務局の判断を保証するものではありません。** 最終的な頒布可否は運営事務局が判断します。

## できること

| チェック | 内容 |
|---|---|
| 奥付チェック | 書名、サークル名／発行責任者名、連絡先、初回発行日、印刷所名が、技書博の規定どおりに書かれているかを確認します |
| 一次レビュー | 表紙・目次・まえがき・あとがきから内容面のリスクを推定し、内容チェックをすすめる強さを決めます |
| 内容チェック（任意） | 本文のテキストが頒布基準（全年齢、違法・危険な手法、公序良俗、行動規範、企業の宣伝規定）に触れないかを確認します |

対応している入力は次のとおりです。

- **PDF**：判定はPDFで行います。
- **Re:VIEW・Vivliostyle・Typst・Sphinx のソース**：直す場所を示すための補助です。実際の出版プロジェクトでの検証は十分でないため、最終的な確認はビルド後のPDFで行ってください。

## できないこと

- **画像の判定はしません。** 表紙・裏表紙・挿絵は運営事務局が確認しますが、このスキルは見直しの観点を示すだけです。
- スキャンして作ったPDFなど、テキストを取り出せないPDFの内容チェックはできません（奥付はページを画像として読んで確認します）。
- 二次創作の表現、著作権の背後関係、技術的な正しさは判断しません。運営事務局も、見本誌ではこれらを判断しません。
- 縦書きの本は未検証です。

## 出版前の原稿の扱い

このスキルが扱うのは、出版前の原稿です。スキルは Claude に対して、原稿を見本誌チェック以外の目的に使わないこと、外部に送らないこと、記憶に残さないこと、作業ファイルを削除することを指示しています。

ただし、**利用するAIサービスが会話やファイルをモデルの学習に使うかどうかは、サービス側の設定で決まります。スキルからは制御できません。** 原稿を渡す前に、ご利用のサービスの設定で、学習に使わない設定になっているかを必ず確認してください。

## インストール

### Claude Code

スキルのフォルダを、個人用のスキルの置き場所にコピーします。

```bash
git clone https://github.com/gishohaku/samplebook-check.git
cp -r samplebook-check/skills/gishohaku-samplebook-check ~/.claude/skills/
```

特定のプロジェクトだけで使う場合は、プロジェクトの `.claude/skills/` にコピーします。スキルの置き場所についての最新の情報は、[Claude Code のドキュメント](https://code.claude.com/docs/en/skills)を参照してください。

### Claude のアプリ（claude.ai など）

配布用のファイルを作り、スキルとしてアップロードします。

```bash
./tools/build.sh    # dist/gishohaku-samplebook-check.skill ができる
```

アップロードの手順は、[Claude のヘルプセンター](https://support.claude.com)を参照してください。

### 必要なもの

スクリプトは次のものを使います。Claude のアプリの実行環境には、通常そろっています。

- Python 3.9 以上、`PyYAML`、`Pillow`（`pip install -r requirements.txt`）
- poppler（`pdftotext`、`pdftoppm`、`pdfimages`、`pdfinfo`）
- `poppler-data`（フォントを埋め込んでいない日本語PDFを読むために必要です。ない場合はスキルが導入方法を案内します）

## 使い方

PDFを添付して、たとえば次のように頼みます。

> 技書博に出す新刊です。見本誌を提出する前にチェックしてください。

スキルは次の順に進めます。

1. 奥付を確認します。本の種別（書籍／フリーペーパーなど）や印刷形態がわからないときだけ、質問します。
2. 奥付の結果を表で示します。
3. 奥付に問題がなければ、「内容のチェックをしますか？」と尋ねます。目次やまえがきから内容面のリスクが高いと推定した場合は、内容チェックを強くすすめます。
4. 内容チェックをした場合は、本文テキストの指摘と、ご自身で確認してほしい観点（画像、連絡先が実際に使えるか、など）を示します。

判定には次の記号を使います。

| 記号 | 意味 |
|---|---|
| ✅ | 問題なし |
| ⚠️ | 要確認（頒布はできそうだが、直すことをすすめる。または人の判断が要る） |
| ❌ | 要修正（このままでは頒布できない可能性が高い） |
| ➖ | 対象外（種別や印刷形態により不要） |

## リポジトリの構成

```
.
├── skills/gishohaku-samplebook-check/   スキル本体（この中身だけを配布する）
│   ├── SKILL.md                         手順と判定の記号
│   ├── references/                      判定の基準（公式ドキュメントの要約）
│   ├── scripts/                         PDF・ソースから情報を取り出すスクリプト
│   └── evals/                           Claude の振る舞いを確かめるテストケース（配布ファイルには含めない）
├── tests/                               スクリプトの回帰テストと、テスト用の合成PDF
├── tools/                               配布ファイルの作成などの補助スクリプト
└── .github/workflows/test.yml           回帰テストとビルドの自動実行
```

## 判定の基準と公式ドキュメント

判定の基準は、技書博の次の公式ドキュメントをもとに、`skills/gishohaku-samplebook-check/references/` に要約しています。公式ドキュメントとこのスキルは、どちらも技書博のスタッフによるものです。両者の内容が食い違う場合は、公式ドキュメントが優先します。規約が改訂された場合は、原文から要約を更新してください。各ファイルの冒頭に、もとにした時点を書いてあります。

| ドキュメント | 書かれていること | このスキルでの使いどころ |
|---|---|---|
| [行動規範](https://gishohaku.dev/code-of-conduct) | 参加者全員に適用される最上位のルール。ハラスメントと差別の禁止、性的なコンテンツの持ち込み禁止、個人情報と著作権の扱い、商業活動の制限など | 内容チェックの「行動規範」カテゴリの根拠 |
| [見本誌の提出](https://gishohaku.notion.site/samplebook-submissions) | 見本誌を提出する目的と対象、運営が確認する項目、頒布できない内容の例、OSINTなどの本に付く条件、運営が判断しないこと | 内容チェック全体と一次レビューの根拠 |
| [本への奥付記載について](https://gishohaku.notion.site/colophon-explanation) | 奥付に必須の6項目、フリーペーパーで省略できる項目、連絡先として認められるもの、印刷後に不備が見つかったときの対処 | 奥付チェックの根拠 |
| [サークル向け重要説明事項](https://gishohaku.notion.site/booth-important-explanation) | 出展の条件、頒布できる物品と頒布条件、禁止事項、企業の宣伝に関する規定 | 全年齢の原則と、企業の宣伝規定の根拠 |

## 開発

### 回帰テスト

スクリプトや正規表現を直したら、必ず実行してください。合成したPDFにスクリプトをかけ、出力が期待どおりかを確かめます。実在の本は含まれていません。

```bash
pip install -r requirements.txt
python tests/run_tests.py
```

テスト用のPDFを作り直す場合は、次を実行します（PyMuPDF と日本語フォント IPAゴシックが必要です）。

```bash
pip install -r requirements-dev.txt
python tests/make_fixtures.py
./tools/sync_eval_fixtures.sh    # evals のケースにも同じPDFをコピーする
```

### 振る舞いテスト

`skills/gishohaku-samplebook-check/evals/` に、Claude の判定そのものを確かめるケースがあります。奥付の通過後に内容チェックを尋ねるか、必須の注意書きがない本を ❌ とするか、などです。各ケースは、依頼文（`prompt.md`）、期待する結果（`case.yaml`）、確認項目（`graders/`）、入力のPDF（`files/`）からなります。

実行するとモデルの利用料金がかかります。Claude Code の `claude plugin eval` で実行できます。

### 配布ファイルの作成

```bash
./tools/build.sh
```
